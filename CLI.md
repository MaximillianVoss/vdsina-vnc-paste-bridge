# CLI и локальный API

Требуется Python 3.10+ со стандартной библиотекой. CLI готовит пакет и выдаёт его расширению. Передача в VNC запускается отдельно в панели браузера.

## Подготовить пакет

Из корня проекта:

```powershell
python -B -m cli pack examples/command.txt --out runtime/packet.json
```

Исходный файл должен содержать печатные ASCII-символы в UTF-8 без BOM. По умолчанию переводы строк запрещены. Для LF используйте `--multiline`; каждый LF будет означать Enter при последующей передаче. CR, CRLF, Tab, Unicode и прочие управляющие символы отклоняются. CLI сохраняет исходный текст точно, включая разрешённый завершающий LF; собственный Enter не добавляет.

Текст ограничен 32768 байтами. Параметры: `--batch-size` 1..256, `--character-delay-ms` 8..100, `--batch-delay-ms` 80..2000; значения по умолчанию — 256, 12 и 120. Размер части задаёт очередь, а не одну массовую вставку.

## Выдать пакет через API

```powershell
python -B -m cli serve --packet runtime/packet.json --connection runtime/connection.json --port 8765
```

В PowerShell оба шага объединяет:

```powershell
.\Start-Bridge.ps1 -TextFile '.\examples\command.txt'
```

`-PythonPath` выбирает конкретный исполняемый файл Python. Без него launcher использует `py -3`, затем `python` из PATH. Для другого порта добавьте `-Port 8766`, для LF — `-Multiline`.

Импортируйте `runtime/connection.json` в панель расширения. API хранит один проверенный пакет в памяти и слушает только `127.0.0.1`; сменить интерфейс привязки нельзя. Для остановки нажмите Ctrl+C. После нового запуска токен меняется и файл подключения нужно импортировать заново.

Файл подключения содержит действующий Bearer-токен. Каталог `runtime/` исключён из Git и архивов проекта. Не включайте файл в отчёты или скриншоты. На POSIX новый файл создаётся с правами 0600; в Windows доступ зависит от ACL выбранного каталога. Токен и исходный текст в консоль не печатаются.

## HTTP-контракт

Только `GET /v1/packet` и `GET /v1/health`, оба с `Authorization: Bearer <token>`. Host должен точно соответствовать `127.0.0.1:<порт>`. Другие маршруты — 404; записывающие методы — 405 после авторизации. CORS-разрешений нет; ответы используют `Cache-Control: no-store`. Запросы, заголовки и токены не журналируются.

При загрузке проверяются exact keys, schema, SHA-256, число символов, байты и границы параметров. Ложные hash/counts, лишние или повторяющиеся поля останавливают запуск. Пакет не выполняется, shell не запускается. Расширение читает только фиксированный `/v1/packet` после ручного импорта файла подключения, затем показывает предпросмотр.

Проверить CLI и реальный loopback HTTP API:

```powershell
python -B -m unittest discover -s tests -p test_cli.py -v
```

Эти проверки используют временные файлы и локальный порт; они не подтверждают доставку в VNC.
